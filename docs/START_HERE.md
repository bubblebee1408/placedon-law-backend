# Start here

The one onboarding page: what the system is, where the code lives, and how to run, test,
change and deploy it from a fresh laptop with nothing but Docker. Where this page and the code
disagree, the code wins; fix this page. The rules every change must obey are in
[../CLAUDE.md](../CLAUDE.md), and they bind whatever this page says.

Deeper references: [ARCHITECTURE.md](architecture/ARCHITECTURE.md) (every product, agent,
model and source), [REPO_MAP.md](REPO_MAP.md) (one line per module, generated by
`python3 scripts/repo_map.py`), [../CONTRIBUTING.md](../CONTRIBUTING.md) (how a change gets
accepted).

## 1. What this is

**Placedon** is an evidence-backed legal intelligence layer for Indian in-house legal teams.
It answers questions about Indian corporate law, reviews documents and contracts, and says
which bodies of law a corporate event engages. Every answer cites the exact provision, its
amending instrument and the date it came into force, or it refuses and says why. **Code
decides legal status, authority and dates; a model may only read, extract, label and
phrase; a lawyer attests before anything is VERIFIED.**

```
 browser
   │  HTTPS
   ▼
 placedon.com — Next.js on Vercel            (separate repo: placedon-claude-legal-3300)
   │  server-side only, with the service key  PLACEDON_GATEWAY_KEY = PLACEDON_GATEWAY_SERVICE_KEY
   ▼
 FastAPI gateway on Azure App Service         (this repo: ops/asgi.py → gateway/app.py)
   │  placedon-api-hyd, Hyderabad              /v1 engine routes · /v2 verbs · job worker
   │                                           in the same box (python -m gateway.worker --serve)
   ├──► Postgres 16, FORCE row-level security  (placedon-pg-uae, UAE North; role placedon_app,
   │      on every tenant table                 NOSUPERUSER NOBYPASSRLS; gateway/migrations/)
   ├──► Azure Blob, private container `vault`  (uploaded files; managed identity, no keys)
   └──► model providers, only through          checker/router.py + gateway/models.py:
          the router                            Azure AI (UAE North, today) · Bedrock ap-south-1
                                                (blocked on the free AWS plan) · Ollama (local only)
```

The engine (`checker/`) is pure Python and decides; the gateway adds keys, tenants, audit,
the job queue and storage. A model is never on the decision path.

## 2. What is held and what is not

`checker/scope.py` is the authority. Run `python3 checker/scope.py` for the live table.

- **Held** (decided on any date): Companies Act, 2013 (`corpus/companies_act/`).
- **Current text only**: SEBI LODR Regulations (today's text, no earlier dates). Sectioned
  into `corpus/sebi_lodr/` and looked up by regulation number, but pending legal review and
  not served in answers.
- **Declared** (in scope, not acquired, so an answer names the gap): LLP Act, SEBI
  ICDR/SAST/PIT/Buyback, FEMA and the FDI rules, IBC, Competition Act, Indian Contract Act,
  Arbitration Act, stamp duty, DPDP Act.
- A question about a declared body is **refused by name, never answered by silence**, and
  the invariant that no obligation exists for an unheld body is a test.

## 3. How a request travels through the code

```
client (web app, MCP, CLI)
  │
  ▼  gateway/          app.py (HTTP), verbs/ (one verb table → REST, MCP and CLI),
  │                    auth.py (hashed keys → tenant), audit.py (hash-chained metadata),
  │                    store/ and migrations/ (Postgres, FORCE RLS on every tenant table)
  │
  ▼  agents/           plans.py (intent → fixed step list), runtime.py (persisted steps,
  │                    bounded correction), one file per intent: research_question.py,
  │                    review_contract.py, review_document.py
  │
  ▼  gateway/jobs.py + worker.py    durable queue (SKIP LOCKED), idempotent steps, saga cancel
  │
  ▼  checker/          the engine:
  │    retrieval       text_search.py (the ranker), ask.py (the ask path), ask_scope.py
  │    law and dates   scope.py, as_of.py, amendment.py, applicability.py, obligations.py,
  │                    events.py (which bodies an event engages), claim_bodies.py
  │    verification    quoted_span.py, ground_span.py, entailment_gate.py, cascade.py
  │    models          model_cascade.py (deterministic → small → large, escalate only on a
  │                    verifier rejection), router.py, azure_model.py, public_only.py
  │    sources         sources/ (tiers: only HELD can verify; terms register in terms.py)
  │    contracts       clauses.py, playbook.py, playbooks/nda_v1.json
  │
  ▼  answer: ANSWERED / PARTIAL / NEEDS_LAWYER / ABSTAINED, with quotes and a trace.
     FAILED means a transport error only and is never shown as a refusal.
```

**The ring firewall** (`checker/rings.py`) is checked by an AST walk in the test gate:
Ring 0 (legal core) may never import Ring 2 (feeds, gateway, sources) or Ring 3 (agents,
forecast). A probability can never reach a legal decision.

## 5. Where each kind of change belongs

| You want to… | Start in | And never forget |
|---|---|---|
| Add an API, MCP or CLI action | `gateway/verbs/` (§9) | One entry generates all three surfaces; write verbs stay off MCP |
| Add a task the product can do | `agents/plans.py`, then a new `agents/<intent>.py` | Plans are fixed step lists; a model may pick, never invent |
| Add a body of law | `checker/scope.py`, then an `ingest_*`/`acquire_*` script | Promotion to held needs acquisition, hashing, cross-check and a lawyer spot-check |
| Add an outside source | `checker/sources/` plus a record in `terms.py` | No record, no fetch; never work around robots rules or a WAF |
| Add a table | `gateway/migrations/NNN_*.sql` (§8) | Tenant tables get FORCE RLS; `make test-db` proves it |
| Change retrieval | `checker/text_search.py` | Measure on the dev split only (`scripts/retrieval_recall.py`); the held-out split is spent |
| Call a model | `checker/router.py`, `checker/model_cascade.py` | Client documents only to accepted regions; UNPRICED is never ₹0 |
| Work on review tables (H4) | `checker/review_grid.py` and `agents/review_grid.py` | See the naming note below — three names, one feature |

**Naming, because three names mean one feature here.** The review-table feature is
`review_grid` **in the code** (`checker/review_grid.py` holds the cells, the states and the
CSV export; `agents/review_grid.py` runs one queue job per cell) and `review_table.*` **in
the verbs** (`review_table.create`, `.status`, `.export`), which is the name a user sees.
**`checker/review_table.py` is a different, older module**: the human-review accounting for
the eleven benchmark fixture proposals. It decides nothing and is unrelated to H4.

## 6. Run it locally

Needs Docker Desktop (or Docker Engine with compose) and `make`. Nothing else: no local
Python, no local Postgres, no keys.

```bash
git clone https://github.com/bubblebee1408/placedon-law-backend.git && cd placedon-law-backend
make dev      # writes .env (random service key), builds, starts db + migrate + gateway + worker,
              # then checks /v1/health reports postgres, a job queue and a vault
curl -s localhost:8000/v1/health | python3 -m json.tool
```

| Service | What it does |
|---|---|
| `db` | Postgres 16 on `localhost:55432`. `ops/dev/initdb/` creates `placedon_app` (the same SQL CI runs) and the `placedon` database it owns |
| `migrate` | One-shot: `scripts/migrate.py --apply` as `placedon_app` with a superuser backup first, then `ops/dev/bootstrap.sql` (sign-in role, local tenant and actor) |
| `gateway` | `uvicorn ops.asgi:app` on `localhost:8000`, the same entrypoint production serves |
| `worker` | `python -m gateway.worker --serve`, draining the local tenant's queue |

Call a verb with the key `make dev` put in `.env`:

```bash
KEY=$(grep ^PLACEDON_GATEWAY_SERVICE_KEY= .env | cut -d= -f2)
curl -s -H "Authorization: Bearer $KEY" localhost:8000/v2/... # list verbs: make shell, then
PYTHONPATH=. python3 gateway/cli.py --help                    # inside the container
```

Other targets: `make logs`, `make shell` (a shell in the image, repo at `/app`), `make down`,
`make reset` (also deletes the local database, vault and backups). The source is
bind-mounted, so after a code change run `docker compose restart gateway worker`.

**Live model answers** need a provider key in `.env` (see the comments there and
[INTEGRATIONS_CHECKLIST.md](guides/INTEGRATIONS_CHECKLIST.md)). Without one, every model
path refuses by name; nothing else is affected. **The web app** runs from its own repo and
points at `http://localhost:8000` with the same service key as its `PLACEDON_GATEWAY_KEY`.

Without Docker: `./setup.sh` installs the Python dependencies, and
[RUN_LOCALLY.md](guides/RUN_LOCALLY.md) runs against a Postgres you manage yourself.

## 7. Test

```bash
make test       # the repository gate, exactly as CI runs it: read the HARNESS_RESULT line
make test-db    # live-database regressions + the row-level security proof, as CI runs them
```

- The gate is **keyless and offline**: deterministic model stand-ins, no network, no
  database. A suite that prints no count, or fewer checks than its floor in
  `scripts/suite_floors.json`, fails. One gate at a time (a lock enforces it).
- There is no pytest. A module tests itself in `_test()` and prints `N/M passed`; add it to
  `scripts/run_tests.sh` (see [CONTRIBUTING.md](../CONTRIBUTING.md)).
- `make test-db` runs `scripts/db_regressions.sh`, which CI also runs. Each script makes and
  drops its own `placedon_throwaway_*` database; your local data is untouched.
- Other useful runs: `PYTHONPATH=. python3 eval/goldset/run.py` (gold set, dev split),
  `python3 checker/scope.py` (what is held).

## 8. Add a migration

1. Add `gateway/migrations/NNN_short_name.sql`, the next number, wrapped in `BEGIN; … COMMIT;`.
   Every tenant table gets `ENABLE` **and** `FORCE ROW LEVEL SECURITY` plus a
   `tenant_isolation` policy on `current_setting('app.tenant_id')`; copy an existing one.
2. Never edit a migration that has been applied anywhere: `scripts/migrate.py` re-hashes
   applied files and refuses to run if one changed. Write a new migration instead.
3. `make migrate` applies it locally (backup first, as `placedon_app`; it refuses a superuser).
4. `make test-db` proves isolation (`scripts/rls_integration.py` must cover the new table).
5. Deploy applies it to production the same way, before the new code goes live (§10).

## 9. Add a verb (an API, MCP and CLI action at once)

1. Write the handler `def _my_verb(args: dict, ctx: Context) -> dict` in the file of
   `gateway/verbs/` for its domain (`vault.py`, `drafts.py`, `review_table.py`, ...; the list,
   one line each, is in `gateway/verbs/__init__.py`), importing what it uses from the owning
   module (`from gateway.verbs.core import Context, _refuse`). If other code imports it from
   `gateway.verbs`, add it to the re-exports in `gateway/verbs/__init__.py`. In tests, patch a
   name where it is looked up: `gateway.verbs.model_access._ledger`, not `gateway.verbs._ledger`.
2. Add a `Verb(name="area.action", summary=..., inputs=(Field(...), ...), run=_my_verb)` to
   the `VERBS` table in `gateway/verbs/registry.py`. `read_only=True` for reads; a write verb is never exported to MCP, and
   `mcp=False` keeps a read off MCP too.
3. Give it a role in `gateway/roles.py` (`REQUIRED`) if it needs more than `viewer`.
4. Add checks to the `_test()` in `gateway/verbs/selftest.py` (and `gateway/app.py` for HTTP
   behaviour). The parity test fails if REST, MCP and the CLI disagree.
5. `make test`, then try it: `make shell` → `PYTHONPATH=. python3 gateway/cli.py --help`.

## 10. Deploy

Production is Azure resource group `placedon-prod`: App Service `placedon-api-hyd` (Python
3.12, Linux B1) and Postgres Flexible `placedon-pg-uae`. **A `git push` deploys nothing.**
One deploy is, in order:

1. Build a zip of a **git checkout** of the commit (the engine refuses to answer unless
   `git rev-parse HEAD` names its commit, so `.git` ships and Azure's build step is off) plus
   the App Service startup script, which starts the worker and `uvicorn ops.asgi:app`.
2. Back up the database with `pg_dump` as the admin role (`scripts/migrate.py --backup-url`),
   then apply pending migrations as `placedon_app`. The Postgres firewall admits only the web
   app's outbound addresses, so the machine doing this needs a temporary firewall rule.
3. `az webapp deploy --type zip`, then poll `/v1/health` until `checker_commit` is the new
   commit, the store is `postgres`, files are `azure-blob` and a queue is present.

Never change App Service settings during a deploy: Azure restarts and cancels it. Who may
deploy and the one-time Azure setup are kept under [docs/deploy/](deploy/).
