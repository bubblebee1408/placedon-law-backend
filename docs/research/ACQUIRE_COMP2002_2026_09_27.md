## 1. Every URL requested today, and what it answered

Four requests. **All four were to `robots.txt`.** No content request was made to
`indiacode.gov.in` for this instrument — not the handle page, not `SectionPageContent`, not
`/server/api/discover/search/objects`.

| # | URL | Client | Answer | Logged as |
|---|---|---|---|---|
| 0 | `https://indiacode.gov.in/robots.txt` | curl, project UA | **500**, `text/html`, 148 bytes, `<pre>Internal Server Error</pre>` | `BLOCKED` / 500 |
| 1 | `https://indiacode.gov.in/robots.txt` | `checker.robots.fetch_rules()` | **500**, identical | `BLOCKED` / 500 |
| 2 | `https://indiacode.gov.in/robots.txt` | urllib, +6s after #1 | **500**, byte-identical | `BLOCKED` / 500 |
| 3 | `https://www.indiacode.gov.in/robots.txt` | urllib | no HTTP answer — `CERTIFICATE_VERIFY_FAILED`, hostname mismatch, cert not valid for `www.indiacode.gov.in` | `UNREACHABLE` + transport error |

robots.txt was fetched **first**, before anything else, because it is the gate and not an
afterthought. It is also the one URL whose retrieval is never itself gated by robots.

### What the repo's own gate says about it

```
checker.robots.fetch_rules('https://indiacode.gov.in')
  -> Rules(loaded=False, source='https://indiacode.gov.in/robots.txt HTTP 500')
checker.robots.allowed('https://indiacode.gov.in/server/api/core/items', rules)
  -> False
```

`rules_for_status()` treats a 5xx as **not permission**: a 4xx means no rules are published
(allow), a 5xx means the rules are *undefined* (deny). That is RFC 9309 §2.3.1.4 verbatim — a
crawler **MUST** assume complete disallow. A MUST, not a SHOULD. So `allowed()` returns `False`
for **every** URL on this host today, the REST API included.

### This is not new, and not transient

`https://indiacode.gov.in/robots.txt` answered **502 on 2026-08-31**, on three consecutive
attempts, and that was recorded in this repository at the time —
`corpus/sources/acquisition_gsr700e.json`, seq 0, with the note *"checker.robots fails closed on
5xx per RFC 9309 … so the compliant fetcher declines the bitstream."* Today it is 500, three times.
**A ≥27-day standing outage of the robots file, not a blip.** The gsr700e instrument was escalated
to human retrieval for exactly this reason, and this one lands in the same place for the same
reason.

### The www origin is not a second door

`www.indiacode.gov.in` is *inside* the permitted-host rule — `check_host()` accepts a dot-suffix,
and `ingest_act.py`'s own test asserts `https://www.indiacode.gov.in/x` is permitted. So it was
worth a probe as a distinct origin with a possibly-readable robots.txt. It is not readable: TLS
verification fails on a hostname mismatch, so no HTTP answer was ever heard. Verification was
**not** disabled to get past it — an unverified statute source is worth less than no statute
source (RT-14).

Worth noting as a small defect: that passing test asserts the www host is *permitted*, which is
true of the host rule and false of reality. Nothing can be fetched from it.

### No control probe was made, deliberately

`docs/policy/ACQUISITION_POLICY.md` asks for a control probe when several endpoints on one host fail —
it is what distinguishes "the host is down" from "the host is refusing us", and those lead to
opposite retry decisions. **A control probe is a content request, and robots wins.** So none was
made, and this log therefore records **no claim** about whether `/server/api` is up right now.

The measurements in the task brief — `/server/api` answering 200 `application/hal+json` with 80
link relations, and `query=dc.identifier.section_number:*&dsoType=item` reporting **74,821**
section-bearing items — are **the founder's measurements, attributed to the founder, and not
reproduced here.** They are not in the acquisition log, because logging an attempt I did not make
is the one thing an acquisition log exists to prevent.

### Two traps for whoever confirms it in a browser

**(1) The year in the actid will not say 2002.** The Competition Act, 2002 received assent in
**January 2003** and is commonly cited as **Act No. 12 of 2003**. The Companies Act 2013 (Act 18
of 2013) is `AC_CEN_22_29_00008_201318_1517807327856` — note the `201318` = year 2013, act 18. By
that pattern the Competition Act's segment should read **`200312`**, not anything containing 2002.

That is a **sanity check on what you read off the page. It is a LEAD, not a source.** "12 of 2003"
must be read off India Code itself before it is recorded anywhere — the same discipline
`PRINCIPAL_RULES_LEAD` in `checker/provenance.py` imposes on notification numbers. Do not backfill
it from this document.

**(2) The rest of the actid is not derivable.** `22_29_00008` and the trailing epoch-milliseconds
(`1517807327856`) come from nothing you can compute. **Do not complete a partially-read actid by
analogy with the Companies Act's.** A wrong actid returns a *different* Act's sections as
well-formed JSON with real statutory text and a clean sha256, and nothing downstream can tell —
which is precisely why `ingest_act.py` refuses rather than guessing.

## 6. Current-text-only is the honest status

The Competition (Amendment) Act, 2023 changed the combination thresholds and inserted provisions.
India Code publishes **one consolidated current text** per Act — not a dated series. So whatever we
eventually acquire answers *"what does the Competition Act say now"* and is **silent on every
earlier date**, with the 2023 changes already folded in and not separable.

This must not be dressed up as historical reconstruction. Using a current consolidated text as
pre-amendment ground truth is the retracted mistake already on the books in
`docs/evidence/RETRACTIONS.md`, and it is why `scope.CURRENT_ONLY` exists with `point_in_time = False`.

## 7. Two findings worth the founder's attention

**(a) `scripts/ingest_act.py` does not consult the robots gate at all.** `_get()` calls
`check_host()`, then `ssl_context()`, then `urllib.request.urlopen` — no `allowed()`, no `Fetcher`,
no `checker.robots` rules. The module imports `USER_AGENT` and `ssl_context` from `checker.robots`
and skips the part that says no. So the one script in this repository that fetches statutes is the
one script that cannot be stopped by robots.txt, and the Companies Act's 527 sections were fetched
through it. Not fixed here — `ingest_act.py` is off-limits by instruction — but it is why "the
REST API is live and open" and "the REST API is permitted" have been able to look like the same
statement.

**(b) The four-state taxonomy has no 5xx member, so a broken robots file is filed as a refusal.**
`ACCESSIBILITY_STATES` is `(ACCESSIBLE, BLOCKED, UNREACHABLE, NOT_FOUND)`. A 500 is none of them:
the host answered (so not `UNREACHABLE`, which is defined as "never answered"), it was not a 403
(so not really `BLOCKED`), and the path is not wrong (so not `NOT_FOUND`). These records follow the
gsr700e precedent — `BLOCKED` with the status carried — so the two are comparable, rather than
inventing a fifth state for one probe.

The cost of that choice, stated plainly: `BLOCKED` is never-retryable, so
`summary()['never_retry_automatically']` now lists `https://indiacode.gov.in/robots.txt` — **the
one URL that MUST be re-read before any future attempt on this host.** The list is a fetch-policy
output, and it currently tells you never to check the gate. `checker/provenance.py` was not edited;
this is a taxonomy gap for a decision, not something to paper over in a note field. A fifth state
(`SERVER_ERROR`, retryable, distinct from both a refusal and an outage) would be the honest fix.

## 8. Handoff

A person in a browser is **not** subject to this gate — a person is not a crawler, the same
reasoning already recorded in the gsr700e handoff. So this is a ~5-minute human task:

1. Open `indiacode.gov.in` in a browser, find **"The Competition Act, 2002"** in the Central Acts
   listing.
2. Copy the **handle URL** from the address bar — `https://indiacode.gov.in/handle/123456789/<n>`.
3. Copy the **actid** — `AC_CEN_…`, in the query string of any per-section link on that page.
4. Sanity-check the actid's year/number segment reads `200312` (see §2, trap 1). If it does not,
   **stop** and report what it does read — do not adjust it to match.
5. Paste both into `ACTS['comp2002']` with the exact URL each was read from.
6. Re-read `robots.txt` before any automated fetch. If it is still 5xx, the enumeration and the
   section fetches remain closed even with a confirmed actid — and §3's scoping problem is still
   unsolved behind it.

Full handoff text is in `reports/acquisition_comp2002.json` under `handoff`.
