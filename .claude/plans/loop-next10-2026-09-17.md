## Iteration protocol
1. Read this file; `git -C ~/PlacedOn/placedon-law-backend log --oneline -5`; `git status --short`.
2. If a job agent is running (Status `running`), do nothing but wait: schedule a 1800 s fallback wakeup.
   Agent completion arrives as a task notification and wakes the loop.
3. Otherwise take the first row whose Status is `ready` and whose dependencies are `complete`.
   Launch its **implementer** (background Agent, prompt = the job card below + the Common rules). Record
   the agent id in the row. Status → `running`.
4. When an implementer returns: Status → `verifying`; launch the **verifier** (background Agent, read-only,
   fresh context, prompt = Verifier template + the job card). Record its id.
5. When the verifier returns: do **check 3** in the main session (below). PASS on both → push, Status
   `complete`, evidence recorded. FAIL → send the findings to the implementer (SendMessage to its id),
   Status `fixing`; after the fix, verify again. Two failed rounds → `blocked`, reason recorded.
6. Read-only jobs (SITE-2) may run beside ONE code job. Never two code jobs at once (8.6 GB Mac, shared
   working tree, 81 s pre-commit gate).
7. If an agent died (usage/session limit): check `git log`, `git status` and the files it names BEFORE
   relaunching; resume it with SendMessage (its context survives) rather than a fresh agent.
8. When every row is `complete` or `blocked`: write `docs/NEXT10_REPORT_2026_09_17.md`, commit, push,
   PushNotification, ScheduleWakeup stop.

## Checked three times (the founder's rule)
- **Check 1 — implementer:** tests written first and seen failing (RED), then passing; full gate
  `bash scripts/run_tests.sh` GREEN; commit (the pre-commit hook re-runs the gate). No push.
- **Check 2 — verifier agent:** a different agent with no stake in the change. Reads the commit diff,
  re-runs the job's own tests and the gate, and makes at least three concrete attempts to break the claim
  (wrong input, stale state, a case the tests don't cover). Returns PASS or FAIL with evidence. It never
  edits files and never commits.
- **Check 3 — main session:** reads the diff; re-runs the gate and the job's acceptance command; checks two
  claims by hand against the files/URLs; only then pushes `loop/bookmark-godseye-v0`.
